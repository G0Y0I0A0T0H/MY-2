# متجرك — منصة إنشاء وإدارة متاجر إلكترونية

منصة عربية متعددة المستأجرين (multi-tenant) لإنشاء متاجر إلكترونية جاهزة، كل متجر على نطاق فرعي خاص به.

> **اسم المنصة** مضبوط في مكان واحد: `src/config/site.ts` (أو متغير البيئة `NEXT_PUBLIC_SITE_NAME`).
> غيّره هناك وسينعكس على كل الواجهات وشعار «صُنع بواسطة …» في متاجر الباقة المجانية.

---

## التقنيات

| الطبقة | التقنية |
| --- | --- |
| الإطار | Next.js 15 (App Router) + React 19 |
| اللغة | TypeScript |
| الواجهة | TailwindCSS 3 + lucide-react |
| قاعدة البيانات | PostgreSQL + Prisma |
| الجلسات | JWT موقّع بـ `jose` في كوكي HttpOnly |
| كلمات المرور | `scrypt` من مكتبة Node القياسية |
| الاتجاه | RTL بالكامل، العربية لغة أساسية |

لا توجد اعتماديات خارجية للألوان أو رفع الصور أو التتبّع — كل شيء داخل المشروع.

---

## قاعدة البيانات المحلية

هذا المشروع يستخدم **عنقود Postgres مخصّصاً على المنفذ 5433**، مستقلاً تماماً عن خدمة
`postgresql-x64-18` التي تعمل على 5432 (لم يُمَس منها شيء). سبب الفصل: كلمة مرور الخدمة
الأصلية غير معروفة وإعادة تعيينها تتطلب صلاحيات مدير.

- مجلد البيانات: `%LOCALAPPDATA%\matjarak-pg\data`
- كلمة المرور محفوظة في `%LOCALAPPDATA%\matjarak-pg\password.txt` وفي `DATABASE_URL` داخل `.env`
- سجل الخادم: `%LOCALAPPDATA%\matjarak-pg\server.log`

هذا العنقود **لا يبدأ تلقائياً مع الويندوز**. بعد إعادة تشغيل الجهاز:

```bash
npm run db:server:start
```

```bash
npm run db:server:stop
```

```bash
npm run db:server:status
```

للانتقال إلى خادم Postgres آخر (خدمتك الأصلية أو خادم إنتاج) يكفي تعديل `DATABASE_URL`
في `.env` — لا شيء آخر في المشروع مرتبط بهذا العنقود.

## التشغيل محلياً

```bash
npm install
```

انسخ متغيرات البيئة ثم عدّلها:

```bash
copy .env.example .env
```

تأكد أن خادم قاعدة البيانات يعمل:

```bash
npm run db:server:start
```

أنشئ الجداول وعبّئ البيانات التجريبية وابنِ فهرس البحث:

```bash
npm run db:push
```

```bash
npm run db:seed
```

```bash
npm run db:index
```

شغّل المشروع:

```bash
npm run dev
```

### الروابط بعد التشغيل

| الصفحة | الرابط |
| --- | --- |
| الموقع التسويقي | http://localhost:3000 |
| لوحة تحكم المنصة | http://localhost:3000/admin |
| لوحة تحكم صاحب المتجر | http://localhost:3000/store-admin |
| المتجر التجريبي | http://demo.localhost:3000 |

بيانات الدخول بعد `db:seed`:

- **مالك المنصة:** القيم المضبوطة في `.env` (`PLATFORM_ADMIN_EMAIL` و`PLATFORM_ADMIN_PASSWORD`)
- **صاحب المتجر التجريبي:** `demo@matjarak.com` / `demo12345`

لإنشاء حساب إدارة جديد أو تغيير كلمة مروره في أي وقت:

```bash
npm run admin -- your@email.com yourPassword "اسمك"
```

ولعرض حسابات الإدارة الحالية:

```bash
npm run admin -- --list
```

> النطاقات الفرعية على `localhost` تعمل مباشرة في Chrome وEdge وFirefox
> (`demo.localhost:3000`). للتصفح بدون نطاق فرعي استخدم `http://localhost:3000/s/demo`.

## الوحدات (Modules)

منطق النطاق مفصول في `src/modules/`، وكل وحدة تُستبدل بخدمة خارجية دون المساس بالباقي.
التفاصيل في [src/modules/README.md](src/modules/README.md).

| الوحدة | تفعل ماذا |
| --- | --- |
| `inventory` | المتغيّرات (لون×مقاس) ومخزون كل منها، والتوفّر اللحظي |
| `search` | التطبيع العربي، البحث التنبؤي، الأكثر بحثاً، الفلاتر الديناميكية |
| `payments` | مزوّدو الدفع والتقسيط وحساب القسط الشهري |
| `pricing` | الكوبونات والحساب المرجعي لإجمالي السلة |
| `shipping` | المحافظات ومناطق الشحن وقواعد الشحن المجاني |
| `geo` | تخمين محافظة الزائر من الـ IP |
| `orders` | إنشاء الطلب والتحقق من المخزون والأسعار |
| `recommendations` | «مقترح لك» و«شوهد سابقاً» |
| `i18n` | قواميس ar/en واختيار اللغة |

## ملاحظات على التنفيذ

**البحث العربي.** الكلمة تُطبَّع قبل الفهرسة والبحث (حذف التشكيل، توحيد أ/إ/آ→ا،
ة→ه، ى→ي، الأرقام العربية→لاتينية)، فيجد «احذيه» نتائج «أحذية». وعند فشل المطابقة
الحرفية يعمل مسار احتياطي متسامح مع الأخطاء الإملائية («تيشرت» → «تيشيرت») يُحسب
بمعامل Dice في الكود.

> **لماذا لا يُحسب في قاعدة البيانات؟** امتداد `pg_trgm` لا يولّد أي trigram للنص
> العربي — يعامل حروفه كفواصل لا كحروف — فيعطي تشابهاً صفرياً دائماً. الفهرس الذي
> ينشئه `npm run db:index` يفيد الأسماء اللاتينية، والمطابقة العربية في الكود.
> هذه هي النقطة الطبيعية للانتقال إلى Meilisearch أو Algolia عند كبر الكتالوج:
> يكفي تبديل جسم `searchProducts()` داخل وحدة البحث.

**المخزون اللحظي.** المخزون الحقيقي على مستوى المتغيّر (لون+مقاس) في جدول
`ProductVariant`. صفحة المنتج تستعلم عن التوفّر كل 25 ثانية وعند عودة التبويب،
فتُعطَّل الألوان والمقاسات التي نفدت ويتحوّل الزر إلى «انتهى من المخزون» بلا إعادة
تحميل. (استقصاء دوري لا WebSocket — أبسط وأوثق على الاستضافات بلا حالة.)

**السلة.** المتصفح يحفظ مراجع الأسطر فقط (معرّف المنتج، اللون، المقاس، الكمية).
الأسعار والخصم والشحن والتوفّر تُحسب في `POST /api/storefront/[tenant]/cart` في
كل تغيير، فلا أثر لأي تلاعب في التخزين المحلي، وتنقص الكمية تلقائياً لما هو متاح.

**الدفع والتقسيط.** المزوّدون معرَّفون في `modules/payments/providers.ts`، ويفعّل كل
متجر ما يناسبه من `/store-admin/payments`. قيمة القسط الشهري تُحسب وتُعرض بجانب
السعر دائماً. الربط الفعلي بالبوابات يحتاج مفاتيح إنتاج؛ حتى ذلك يُسجَّل الطلب
ويُنسَّق التحصيل — نقطة الربط الوحيدة هي `initiatePayment()`.

**تحديد الموقع.** يُقرأ من هيدرات الـ CDN (Vercel أو Cloudflare) بلا أي طلب شبكة،
أو من خدمة خارجية إن ضُبط `GEOIP_LOOKUP_URL`. عند تعذّر التحديد لا نخمّن: يختار
العميل محافظته يدوياً.

**الترجمة.** البنية كاملة (`modules/i18n`) واكتشاف تلقائي للغة المتصفح مع حفظ
الاختيار في كوكي. **واجهة المتجر مترجمة بالكامل ar/en**؛ أما اللوحتان الإداريتان
فعربيتان فقط في هذه المرحلة — الآلية جاهزة لتوسيعهما بإضافة القواميس.

## بنية المشروع

```
prisma/
  schema.prisma          سكيما قاعدة البيانات
  seed.ts                حساب الإدارة + المتجر التجريبي
scripts/local-db.mjs     تشغيل/إيقاف خادم Postgres المخصّص للمشروع
src/
  middleware.ts          توجيه النطاقات الفرعية والدومينات المخصّصة
  config/site.ts         هوية المنصة (الاسم، النطاق الجذر)
  lib/                   طبقة مشتركة: prisma، auth، money، colors، whatsapp…
  components/            مكوّنات واجهة عامة (أزرار، حقول، بطاقات، إحصائيات)
  features/
    platform-admin/      لوحة مالك المنصة: إجراءات + مكوّنات
    store-admin/         لوحة صاحب المتجر
    storefront/          واجهة المتجر: السلة، المنتج، الدفع
  app/
    page.tsx             الصفحة التسويقية
    admin/               /admin — محمية بجلسة مالك المنصة
    store-admin/         /store-admin — محمية بجلسة صاحب المتجر
    s/[tenant]/          قالب المتجر (يصله الطلب بعد إعادة الكتابة من middleware)
    api/                 رفع الصور، تتبّع الزيارات، الصور البديلة
```

**لإضافة قالب متجر جديد لاحقاً:** انسخ `src/features/storefront` إلى مجلد قالب جديد،
وأضف حقل `template` في نموذج `Store`، ثم اختر المكوّنات في `src/app/s/[tenant]/layout.tsx`
بناءً على قيمته. باقي الطبقات (السلة، الطلبات، الدفع) مشتركة ولا تحتاج تعديلاً.

## كيف يعمل التوجيه متعدد المستأجرين

`middleware.ts` يقرأ الـ host ويحدّد المتجر:

| العنوان المطلوب | ما يحدث |
| --- | --- |
| `matjarak.com/...` | يمرّ كما هو (الموقع الأساسي واللوحات) |
| `blanco.matjarak.com/product/x` | يُعاد كتابته إلى `/s/blanco/product/x` |
| `shop.client.com/product/x` (دومين مخصص) | يُعاد كتابته إلى `/s/shop.client.com/product/x` |

يُمرَّر الهيدر `x-store-mode: subdomain` حتى تبني صفحات المتجر روابطها بدون البادئة،
بينما تعمل نفس الصفحات على `/s/[slug]` أثناء التطوير. الدالة `getStoreContext()`
في `src/lib/tenant.ts` تتكفّل بذلك وتُرجع `href()` الصحيحة.

## المبالغ المالية

كل الأسعار تُخزَّن **أعداداً صحيحة بالقرش** (`349.99 ج.م = 34999`) لتفادي أخطاء الفاصلة
العائمة. التحويل يمرّ دائماً عبر `src/lib/money.ts`:

- `toMinor('349.99')` → `34999` عند الحفظ
- `formatPrice(34999, 'EGP')` → `349.99 ج.م.` عند العرض

**الأسعار تُقرأ من قاعدة البيانات عند إتمام الطلب** ولا يُوثق بما يرسله المتصفح.

## إشعارات واتساب

عند إتمام أي طلب يُستدعى `notifyStoreOwner()` في `src/lib/whatsapp.ts`:

1. إن ضُبط `WHATSAPP_API_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` (واتساب Cloud API من Meta)
   تُرسل الرسالة تلقائياً لرقم صاحب المتجر.
2. وإلا يُحفظ رابط `wa.me` جاهز بنص الطلب كاملاً في `Order.whatsappLink`، ويظهر في
   لوحة الطلبات كزر «إعادة إرسال تفاصيل الطلب لنفسك».

في الحالتين لا يفشل الطلب أبداً بسبب فشل الإشعار.

## نظام الباقات والإحالة

الباقات معرَّفة في `src/lib/plans.ts` — مكان واحد للتعديل:

| الباقة | المنتجات | شعار المنصة | دومين خاص |
| --- | --- | --- | --- |
| مجانية | حتى 15 | يظهر | لا |
| أساسية | بلا حد | مخفي | نعم |
| متقدمة | بلا حد | مخفي | نعم |

**الإحالة:** لكل متجر `referralCode` فريد. عند إنشاء متجر جديد بكود دعوة صحيح
يُسجَّل في جدول `Referral` ويُمدَّد `planExpiresAt` للمتجر المُحيل 30 يوماً.

## الأمان

- جلستان منفصلتان تماماً: `mtj_platform` لمالك المنصة و`mtj_store` لصاحب المتجر.
- كل استعلامات لوحة صاحب المتجر مقيّدة بـ `storeId` المأخوذ من الجلسة، لا من المتصفح.
- رفع الصور متاح للمستخدمين المسجّلين فقط، بفحص نوع الملف وحجمه.
- كلمات المرور بـ `scrypt` مع ملح عشوائي ومقارنة بزمن ثابت.

## ملاحظات قبل النشر

1. **`AUTH_SECRET`** — ولّد قيمة عشوائية طويلة ولا تستخدم القيمة الافتراضية.
2. **رفع الملفات** — التخزين الحالي على القرص المحلي (`public/uploads`). على
   منصات بلا قرص دائم (Vercel مثلاً) بدّل جسم `storeUpload()` في `src/lib/storage.ts`
   إلى S3 أو Vercel Blob؛ الواجهة لن تتغيّر.
3. **`images.remotePatterns`** في `next.config.ts` مفتوح لكل نطاقات https لتسهيل لصق
   روابط الصور — ضيّقه للنطاقات التي تستخدمها فعلاً.
4. **DNS** — أضف سجل wildcard `*.yourdomain.com` ليعمل أي نطاق فرعي جديد تلقائياً.
5. **بوابات الدفع** — فاليو وباي موب مسجّلتان كطريقتَي دفع في الطلب، والتحصيل يتم
   حالياً بالتنسيق مع العميل. ربط البوابات برمجياً خطوة لاحقة مستقلة.
